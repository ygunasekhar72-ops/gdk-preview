GDK case study v2 — one 3D game, built twice

"Mini GTA 3D" — top-down request, real-3D delivery: an open-world city in the browser. Walk in third person, steal cars (chase camera), knock over pedestrians and earn wanted stars, shake the police, deliver checkpoints for cash. Built twice by AI coding agents in Three.js — once without GDK (just "make it work"), once through the GDK pipeline (declared spec → generated agent team plan → phased build → machine-checked quality gates that reject the build until every rule passes). Both are fully playable below.

WITHOUT GDK 0 gates · 0 tests · unverified

  • Shape: one ~1,440-line game.js + index.html. No spec, no tests, no build, no gates.
  • Look: golden-hour gradient sky, emissive-window towers, merged static geometry (6 draw calls), articulated walker.
  • Timing: variable-delta setAnimationLoop — simulation behavior depends on frame rate.
  • Verification: syntax check + a manual self-review. No test can prove the physics, FSM, or mission loop — reviewers re-read code by hand, every time it changes.

BUILT WITH GDK gates: PASS · 7/7 headless tests

  • Shape: declared gdk.game.json (engine: web, 3D, 60 Hz) → planner roster (netcode phase correctly dropped for single-player) → phased build with per-phase gate runs kept as the audit trail.
  • Look: dusk scene with emissive-window facades, real shadow map following the player, instanced road furniture, declared renderer config (DPR cap, ACES, PCF shadows).
  • Timing: deterministic 60 Hz fixed-timestep sim, render decoupled — same seed + same inputs = identical world, proven over 600 ticks.
  • Verification: a 7-test headless suite (determinism, input clamp, collision, FSM legality, crime events, full bot playtest) printing GDK:ALL-TESTS-PASS — reruns in seconds on every change.

What the gates actually caught during the rebuild

Real defects the gates forced into the open (fixed in the game, never in the gates):
  • Wall-glue collision — cars and pedestrians ground along walls to a standstill; the scripted-playtest gate exposed it → tangent sliding for both.
  • Dead missions after a bust — a BUSTED respawn stranded the FSM in FREE_ROAM so the mission could never complete → fixed (mission persists through arrest).
  • Two test bugs — an FSM case asserting a legal transition must be rejected, and a bot chasing uncatchable moving cars → tests fixed, gates untouched.
Honest comparison: the ungoverned build plays fine and even looks great today — skilled agents ship quality either way. What GDK adds is the part you can't see in a screenshot: proof (determinism, clamps, FSM legality, full-loop playtest rerun in seconds), authority discipline (grep-enforced sim boundary — drop-in ready for server-authoritative multiplayer), and auditability (every phase's gate report is kept). That's the gap it exists to close.
